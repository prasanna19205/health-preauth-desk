# RAG module: Care Supreme pre-authorisation corpus

Indexes one policy wording (Care Supreme, UIN CHIHLIP27061V032627) and a day-care
procedure list, and exposes retrieval tools for the agents.

## Setup (Windows, run inside the `rag` folder)

1. `python -m venv venv`
2. `venv\Scripts\activate`
3. `pip install -r requirements.txt`
4. `copy .env.example .env`
5. `python ingest.py`
   - Builds the index from `data/raw/policy.pdf` and `data/raw/daycare.pdf`.
   - Expected end: 370 total chunks (204 policy + 166 day-care).
   - Safe to run again: unchanged documents are not re-embedded, and chunks from
     replaced documents are removed.
6. `python eval_retrieval.py`
   - Expected end: `hit@5: 30/30 = 100%`.
7. `python test_new_tools.py` (cataract demo of the new tools).

## Configuration (`.env`, see `.env.example`)

EMBED_MODEL, CHROMA_DIR, COLLECTION_NAME, POLICY_PDF, POLICY_VERSION,
DAYCARE_PDF, DAYCARE_VERSION. No keys or secrets are needed (embeddings run locally).
Change a *_VERSION value when you replace a document.

## Data

- `data/raw/policy.pdf`: Care Supreme policy wording (public).
- `data/raw/daycare.pdf`: day-care list generated by `build_daycare_pdf.py` from a
  third-party copy of Care's list. Replace it with the official PDF if one is found.

## Tools (`tools.py`)

Every result dict has: `clause_id`, `doc_id`, `doc_version`, `section_type`, `page`,
`heading`, `text`, `score`. Cite only clauses you have received.

| Tool | Returns |
|---|---|
| `search_corpus(query, section_type=None, k=5, doc_id=None)` | Top-k semantic matches |
| `get_clause(clause_id)` | One exact chunk, or `None` |
| `get_clause_parts(clause_id)` | All parts of a clause in order, e.g. `policy:3.1.1` to `#10`, `[]` if absent |
| `search_modifiers(query, k=3)` | Waiting-period, exclusion and sub-limit matches, best first |
| `check_waiting_period(condition)` | `{condition, listed, matches}`; each match has the clause text and `months_mentioned` |
| `check_daycare(procedure, k=3)` | `{status: listed or not_found, matches, nearest}`; not_found is not proof of exclusion, so escalate if unsure |
| `search_daycare_list(procedure, k=3)` | Semantic matches from the day-care list |
| `list_documents()` | Indexed documents, versions and chunk counts |

`section_type` values: cover, waiting_period, exclusion, sublimit, definition,
annexure, daycare_procedure. Page is where the clause starts.

## Reference case (planned cataract surgery, policy 11 months old)

- Cover: `policy:3.1.1` (starts p.16)
- Waiting period: `policy:Excl02#2` (p.34), 24 months, cataract in the list
- Day-care list: `daycare:p1:item34`
- The wait is not served at 11 months, so do not recommend approval (accident claims are exempt).
